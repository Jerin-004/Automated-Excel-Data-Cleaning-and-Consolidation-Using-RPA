# Automated Excel Data Cleaning and Consolidation Using RPA

## Problem Statement

Organisations routinely receive employee and customer data spread across multiple Excel
workbooks generated by different systems. These files contain inconsistent column names,
mixed date formats, invalid email addresses, negative salaries, duplicate records, and
missing mandatory values. Manually reconciling this data is slow, error-prone, and
produces no audit trail. Even a modest dataset of a few hundred records can take an
experienced analyst an hour or more to clean and consolidate by hand.

## Project Objectives

1. Automatically discover all Excel files in a configured input directory.
2. Extract tabular records from every worksheet in each workbook.
3. Normalise column names and map legacy column-name aliases to canonical names.
4. Clean records: strip whitespace, standardise dates, normalise phones and emails,
   convert numeric fields, and apply configurable categorical mappings.
5. Validate every record against configurable business rules (required fields, salary
   range, email format, date parseability).
6. Detect and separate exact duplicate records and conflicting duplicate records
   (same identifier, different values) across all files in one global pass.
7. Consolidate clean records into a single master Excel workbook with six worksheets.
8. Generate a machine-readable validation-errors CSV and a JSON run summary.
9. Measure actual automation execution time and compare it with a clearly labelled
   estimate of manual processing time.
10. Expose the entire workflow through a Streamlit dashboard with real-time progress,
    data previews, and download buttons.

## Proposed Solution

A Python-based RPA pipeline built on open-source libraries. The pipeline is organised
into 13 explicit stages (see Workflow section). Each stage records its execution time,
passes structured results to the next stage, and handles exceptions without silently
discarding data. All business rules are externalised to `config/settings.json` so that
no code changes are needed to adapt the application to a different organisation.


## Key Features

- 13-stage RPA workflow with per-stage timing and status tracking
- Cross-file duplicate detection (exact and conflicting)
- Configurable column-alias mapping for legacy column names
- Atomic Excel output (temp-file + rename — never corrupts a good output)
- Six-worksheet master workbook with professional formatting and conditional colours
- Real-time Streamlit progress bar driven by actual workflow stages
- Performance analysis: actual timing vs clearly-labelled manual estimate
- 72 automated tests (unit + integration + end-to-end)

## Expected Input Excel Format

The application accepts any `.xlsx` or `.xlsm` file with tabular data. Supported
column names (canonical and aliases) are defined in `column_aliases` in
`config/settings.json`. The current dataset schema is:

| Canonical Column | Accepted Aliases |
|-----------------|-----------------|
| `record_id` | `id`, `emp_id`, `employee_id`, `cust_id` |
| `name` | `full_name`, `employee_name`, `customer_name` |
| `email` | `email_address`, `e_mail`, `email_id` |
| `phone` | `phone_number`, `mobile`, `mobile_number`, `contact_number` |
| `department` | `dept`, `division`, `team` |
| `joining_date` | `join_date`, `date_of_joining`, `start_date`, `hire_date` |
| `salary` | `annual_salary`, `pay`, `ctc`, `compensation` |
| `city` | `location`, `city_name`, `place`, `town` |

Columns not in this list are preserved as-is. Files with completely missing required
columns are reported as failed; processing continues on other files.

## Output Workbook Structure

The master workbook is written to `data/output/Master_Consolidated_<timestamp>.xlsx`
and contains six worksheets:

| Worksheet | Contents |
|-----------|---------|
| `Master_Data` | Consolidated, cleaned, deduplicated records |
| `Data_Quality_Report` | Per-file cleaning operation statistics |
| `Exceptions` | Records that failed validation (with error messages) |
| `Processing_Log` | Per-file status, row counts, timing |
| `Duplicate_Records` | All exact and conflicting duplicate records |
| `Run_Summary` | Overall KPIs and performance metrics |

## Cleaning Rules

| Rule | Behaviour |
|------|-----------|
| Whitespace | Strip leading/trailing spaces from all string cells |
| Name capitalisation | Title-case the `name` column |
| Email normalisation | Lower-case; strip spaces |
| Date standardisation | Parse multiple formats; output as `YYYY-MM-DD` |
| Phone normalisation | Remove `(`, `)`, `-`, `.`, `/`, spaces; preserve leading `+` |
| Numeric conversion | Strip `$`, `£`, `€`, `,` from salary; convert to float |
| Categorical mapping | Map abbreviations to full names (e.g. `hr` → `Human Resources`) |
| Missing-value flagging | Add `_missing_<col>` boolean column for mandatory fields |

Cleaning never fabricates data. Non-convertible values are preserved as-is and
flagged by the validator.

## Validation Rules

| Rule | Severity | Behaviour |
|------|----------|-----------|
| Required field empty | Critical | Record marked INVALID |
| Duplicate `record_id` | Critical | All matching records marked INVALID |
| Invalid email format | Warning | Record marked REVIEW |
| Non-numeric salary | Critical | Record marked INVALID |
| Negative salary | Warning | Record marked REVIEW |
| Unparseable date | Warning | Record marked REVIEW |
| Unmapped categorical value | Warning | Record marked REVIEW |

Records are separated into VALID, REVIEW, and INVALID — never silently discarded.

## Exception Handling Strategy

Every stage wraps its logic in structured exception handling. Failures are recorded
in an `ExceptionHandler` with stage, file, error category, and recommended action.
Critical stages (init, config, discovery) abort the pipeline. Per-file stages
(read, clean, validate, dedup) log the failure and continue with remaining files.
A partial success is reported accurately; no failed run is marked successful.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `pandas segfault` | pandas ≤ 2.x on Python 3.14 | `pip install "pandas>=3.1.0"` |
| `No Excel files found` | Empty or wrong input directory | Check path in sidebar or `settings.json` |
| `CorruptedFileError` | File is not a valid xlsx | Open in Excel and re-save |
| `MissingColumnsError` | Required columns absent | Add alias in `column_aliases` config |
| `OutputWriteError` | Output directory not writable | Check permissions on `data/output/` |
| Streamlit `DuplicateWidgetID` | Page reloaded mid-run | Refresh browser and restart run |

## Known Limitations

1. Very large files (> 100 000 rows) may be slow in the Streamlit preview — the
   preview is capped at 500 rows but the full DataFrame is held in session state.
2. The manual-processing rate (100 records/minute) is a configurable assumption, not
   an experimentally measured value.
3. Multi-sheet workbooks: the reader processes all sheets independently; cross-sheet
   deduplication within a single file is not performed separately from the global pass.
4. The Streamlit dashboard does not support concurrent workflow runs from multiple
   browser tabs — session state is per-tab but output files share a single directory.
5. Password-protected workbooks are not supported.
